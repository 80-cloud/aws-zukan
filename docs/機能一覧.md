# aws-zukan 機能一覧

**バージョン:** 0.1
**作成日:** 2026-06-26

要件定義書の機能要件を、画面・データと対応づけて具体化する。

---

## Phase 1（最初の版）

### サービス図鑑（部品表）

| ID | 機能 | 内容 | 関連画面 |
|---|---|---|---|
| F-SVC-01 | 一覧 | カテゴリ分類で並べ、キーワード検索と絞り込み（カテゴリ・難易度・無料枠有無）ができる | SCR-01 |
| F-SVC-02 | 詳細 | テンプレート項目を表示：一言／使う場面／向かない場面／よく使う部署／本番利用の前提／関連サービス／代替候補／導入の難易度（技術・運用・社内調整）／公式リンク／更新日 | SCR-02 |
| F-SVC-04 | 共通ルール参照 | IAM・ログ・暗号化などの横断ルールは共通ページに置き、詳細から参照リンクで開く（各サービスに重複記載しない） | SCR-02 |
| F-SVC-06 | 実体験つまずき参照 | サービス・構成パターンに「実際に踏んだつまずき」を出典リンクつきで表示する（検証済みの事実のみ・推測は載せない） | SCR-02 / SCR-04 |

### 構成パターン図鑑（設計判断集）

| ID | 機能 | 内容 | 関連画面 |
|---|---|---|---|
| F-PAT-01 | 一覧 | 「何を実現したいか（目的）」から推奨構成を探す。目的でフィルタ | SCR-03 |
| F-PAT-02 | 詳細 | 標準推奨構成／不適合になりやすい構成／必須になりやすい統制／任意要素／適する条件／代替案／評価の8観点 | SCR-04 |
| F-CMP-01 | 比較 | 同じ目的に対する複数構成を、評価の観点ごとに表で並べる | SCR-05 |

### データ・閲覧状態

| ID | 機能 | 内容 |
|---|---|---|
| F-DATA-01 | データ駆動 | サービス・共通ルール・構成パターンを JSON から読み込む。読み込みは `src/api/` 経由 |
| F-FAV-01 | 閲覧状態 | お気に入り・既読を localStorage に保存。欠損しても致命にならない |

## Phase 1.5（既存データの拡張＋ビューで足す・追加実装が軽いもの）

いずれも文章生成（LLM）に頼らず、固定データと派生ビューで実現する。

| ID | 機能 | 内容 | 実現 |
|---|---|---|---|
| F-CHK-01 | 設計レビュー観点チェック | 「ログはあるか／暗号化はあるか／単一障害点はないか」等を構成ごとに確認しレビュー漏れを減らす | `requiredGovernance`＋共通ルール＋評価軸から生成（派生ビュー） |
| F-SVC-07 | 随伴サービス提示 | あるサービスに対し、本番で要る監視・ログ・IAM・バックアップ候補を出す。「動くが企業利用に足りない構成」を防ぐ | Service.`companions[]` |
| F-SVC-08 | コスト注意表示 | NAT Gateway・ALB・Elastic IP・EBS 残存・CloudWatch Logs など見落としやすい課金を注意表示 | Service.`costGotcha` |
| F-SEC-01 | セキュリティ注意カタログ | Public 公開・過剰権限・暗号化なし・ログなし・SSH 全開放 等の注意点を一覧で学べる | antiPatterns＋共通ルール＋realWorldNotes から抽出（派生ビュー） |
| F-PAT-04 | 構成依存関係グラフ | 構成内で各サービスが何の役割かを図で示し、全体を理解しやすくする | ConfigPattern.`stackRoles[]` |
| F-PAT-05 | 事例（シナリオ）検索 | 「オンプレ移行」「子会社統合」「外部公開サイト」など業務課題から構成を探す | ConfigPattern.`scenarioTags[]` |
| F-SVC-09 | 採用判断情報 | 廃止・縮小リスク／リージョン対応／クォータ注意／SLA・可用性／ロックイン度／移行先を表示。「新規採用してよいか」を判断できる | Service.`adoption` |
| F-SVC-10 | 運用情報 | IaC 対応度／バックアップ可否／変更時の影響範囲／障害時の代替／データ越境注意を表示 | Service.`ops` |
| F-SVC-11 | 隠れコスト辞典 | NAT・データ転送・ログ保持・スナップショット・クロス AZ 通信など、想定外請求になりやすい点を横断で一覧 | Service.`costGotcha` の横断ビュー |
| F-SVC-04+ | 共通ルール拡充 | ログ保存設計・タグ設計・権限分離の型を共通ルールに追加（各サービスから参照） | common-rules: logging/tagging/iam-templates |

## Phase 2 以降（将来）

### 組織統制層（大企業・子会社向けの差別化・組織固有値は別管理）

| ID | 機能 | 内容 |
|---|---|---|
| F-GOV-01 | 組織向け情報（基盤） | 承認の要否・標準構成・禁止事項・コスト配賦を別の層として管理（組織ごとに変わる値） |
| F-GOV-02 | 組織統制チェック | 子会社利用・費用配賦・監査ログ・権限委任・アカウント分離を確認 |
| F-GOV-03 | 責任分界表示 | AWS・開発部門・基盤部門・情シス・委託先の担当範囲を示し、運用責任の曖昧さを減らす |
| F-GOV-04 | 導入条件・社内申請一覧 | Direct Connect・WAF・外部公開・個人情報利用などの申請・審査観点を示す |
| F-GOV-05 | 監査証跡の証明方法 | 「このサービスを使っている証跡」をどこから取得するか（CloudTrail 等）を示す。内部監査・ISMS 対応 |
| F-GOV-06 | アカウント配置の推奨 | 共通基盤・ログ保管・セキュリティ・開発・本番・子会社ごとの置き場所例（Organizations 設計） |
| F-GOV-07 | 導入時の関係者マップ | 開発・ネットワーク・セキュリティ・情シス・法務・購買・ベンダーなど、調整漏れを防ぐ関係者一覧 |
| F-GOV-08 | 調達・契約観点 | Marketplace・ライセンス BYOL・Enterprise Support・外部 SaaS 連携の注意（調達審査） |
| F-GOV-09 | 社内標準との差分表示 | 標準構成と比較し、例外申請が必要な点を表示（ガバナンス運用） |
| F-GOV-10 | 実運用の成熟度スコア | 監視・バックアップ・IaC・権限・障害対応の整備度を点数化し改善優先順位を出す（ルールベース） |

### 診断・検知（いずれもルールベース。LLM 文章生成はしない）

| ID | 機能 | 内容 |
|---|---|---|
| F-REV-01 | 要件からの構成診断 | 公開範囲・認証・可用性・データ量・運用人数などを入力し、該当構成と「確認すべき論点」を**決まった文面**で返す |
| F-SEC-02 | セキュリティ検知 | 入力された構成から Public 公開・過剰権限・暗号化なし・単一アカウント運用などを**ルールで**検知 |

### その他

| ID | 機能 | 内容 |
|---|---|---|
| F-PAT-03 | アンチパターン集 | 構成パターンを「不適合」で絞り込んで一覧する表示（新しいデータ実体ではなく絞り込み） |
| F-SVC-03 | サービス拡充 | 残りのサービスをテンプレートに沿って浅く網羅。更新日が古い項目に「要確認」を表示 |
| F-SVC-05 | 鮮度管理 | 各項目の確認日を持ち、一定期間を過ぎたものを自動で「要確認」扱いにする |

## データ規模の方針

| 区分 | 件数の目安 | 掲載の濃さ |
|---|---|---|
| 基盤・頻出 | 30〜50 | 詳細・比較・運用まで厚く（Phase 1 の対象） |
| 専門領域 | 80〜120 | 要約・用途・関連・注意点（Phase 2） |
| 参照用 | 残り | 基本情報・短い用途・公式リンク中心（Phase 2 以降） |

> まず基盤・頻出を厚く仕上げて「成立」させ、残りは検索可能なカタログとして段階的に増やす。
