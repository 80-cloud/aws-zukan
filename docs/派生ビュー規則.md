# aws-zukan 派生ビュー生成規則

**バージョン:** 0.1
**作成日:** 2026-06-26

新しいデータを持たず、既存データ（services / patterns / common-rules）から機械的に組み立てるビューの生成規則。実装が場当たりにならないよう、入力→出力の対応を先に固める。

---

## F-CHK-01 設計レビュー観点チェック（構成パターン単位）

ある構成パターンを開いたとき、確認すべき観点リストを自動生成する。

**入力 → チェック項目:**
1. `pattern.requiredGovernance[]` … 各項目を「__ は満たしているか？」に変換（必ず含める）。
2. 構成内サービス（`recommendedStack`）の `commonRuleRefs[]` を集約 … 該当する共通ルール（network / iam / logging / encryption / backup）を「__ の観点は確認したか？」に変換。重複は1つに畳む。
3. `pattern.evaluation` で **△ または ✕ の軸** … 「この構成は __ が弱い。対策はあるか？」を警告項目として追加。
4. 構成内サービスの `ops.failover` / `ops.backup` が空でない … 「障害時の代替・バックアップは要件に合うか？」を追加。

**出力:** チェック項目の配列（種別＝必須統制 / 共通観点 / 弱点警告）。各項目に出典（どのフィールド由来か）を付ける。

**原則:** 文章生成（LLM）はしない。上記マッピングの単純な集約のみ。

---

## F-SEC-01 セキュリティ注意カタログ（横断ビュー）

セキュリティ上の注意点を全データから集めて一覧する。

**入力 → カタログ項目:**
1. `pattern.antiPatterns[]` のうちセキュリティに関するもの（SSH 全開放・公開範囲過大 等） … `why` を「避ける理由」、対になる `requiredGovernance` を「正しい型」として併記。`source` があれば出典リンク。
2. 共通ルール `network` / `iam` / `encryption` … 「最小許可」「最小権限」「暗号化」の基本を項目化。
3. サービスの `realWorldNotes` のうちセキュリティ系（例：SSH 0.0.0.0/0、RDS 隔離） … 出典つきで「実際にあった注意点」として載せる。
4. `pattern.evaluation.security` が △/✕ の構成 … 「この構成はセキュリティが弱い」と該当構成へリンク。

**出力:** カタログ項目（注意点 / 避ける理由 / 正しい型 / 出典）。重複は畳む。

**原則:** 検知（ユーザー構成を入力して判定）は Phase 2（F-SEC-02・ルールベース）。本ビューは**読み取り専用のカタログ**に留める。

## F-SVC-11 隠れコスト辞典（横断ビュー）

想定外の請求になりやすい点を全サービスから集めて一覧する。

**入力 → 辞典項目:**
1. サービスの `costGotcha`（明示された見落としやすい課金。例：停止中の EBS 残存課金、稼働中ロードバランサの常時課金） … 本文をそのまま「見落としやすい課金」として載せ、サービス詳細へリンク。
2. サービスの `cost.meteredAxes[]` が想定外になりやすい軸（転送量・NAT 付随リソース・ログ量・IOPS・クロス AZ・スナップショット・リクエスト数・保持・残存）を含む … `costGotcha` が無い場合に「課金される軸」として載せる。
3. 併記情報 … `cost.relative`（コスト感 低/中/高）と該当する課金軸を補助表示する。

**出力:** 辞典項目（サービス / 見落としやすい課金 or 課金される軸 / コスト感 / 課金される軸 / サービスへのリンク）。明示された見落としやすい課金を先頭にまとめる。

**原則:** 文章生成（LLM）はしない。**具体額は持たず定性表現に留める**（金額は変動するため公式ページへ送客）。本ビューは**読み取り専用の辞典**。

## F-PAT-05 事例（シナリオ）検索（横断ビュー）

業務課題から、それに該当する構成パターンを探す。構成パターン一覧（目的で絞り込み）の逆向きで、課題を主軸に束ねる。

**入力 → 課題グループ:**
1. 各構成パターンの `scenarioTags[]`（業務課題。例：オンプレ移行・外部公開サイト・チーム開発基盤） … タグごとに該当する構成パターン（`name` / `goal` / 詳細リンク）を集める。
2. 並び順 … 該当する構成が多い課題を上に、同数はタグ名の昇順。
3. 絞り込み … 課題名のキーワードで一覧を絞れる。

**出力:** 課題グループの配列（課題 / 該当件数 / 該当構成パターンへのリンク）。

**原則:** 文章生成（LLM）はしない。`scenarioTags` の集約のみ。本ビューは**読み取り専用**。

---

## F-PAT-04 構成の役割（構成パターン単位）

構成パターン内で、各サービスが何の役割を担うかを示す。

**入力 → 役割項目:**
1. `pattern.stackRoles[]` … 各要素の `serviceId` をサービス詳細へのリンク、`role` を役割の説明として並べる。
2. 並び順 … `stackRoles` の登録順（構成の組み立て順に沿う）。

**出力:** 役割項目（サービス / 役割 / サービス詳細へのリンク）。

**原則:** 文章生成（LLM）はしない。`stackRoles` の表示のみ。本ビューは読み取り専用。

---

## F-PAT-03 不適合になりやすい構成カタログ（横断ビュー）

各構成パターンで「この前提では不適合になりやすい」とされた選択を、サービス単位で集めて逆引きできるようにする。構成の役割（F-PAT-04）の裏返しで、避けやすい選択を主軸に束ねる。

**入力 → サービスグループ:**
1. 各構成パターンの `antiPatterns[]` … `stack[]` に含まれるサービスごとに、その構成（`name` / 詳細リンク）と `why`（不適合になりやすい理由）を集める。`source` があれば出典リンク。
2. 並び順 … 不適合の事例が多いサービスを上に、同数はサービス名の昇順。
3. 絞り込み … サービス名のキーワードで一覧を絞れる。

**出力:** サービスグループの配列（サービス / 該当件数 / 構成へのリンク / 不適合になりやすい理由 / 出典）。

**原則:** 文章生成（LLM）はしない。`antiPatterns` の集約のみ。**断定しない**＝いずれも前提条件つきで、同じサービスでも要件次第で標準的な選択になり得ることを併記する。本ビューは**読み取り専用**。

## F-SVC-05 鮮度管理（サービス単位）

各サービスの確認日（`verifiedAt`）が古くなった、または未確認の項目に「要確認」を出す。情報の経年劣化を可視化する。

**入力 → 表示:**
1. `verifiedAt` が無い（未確認） … 「要確認」を出す。
2. `verifiedAt` が今日からしきい値（既定 180 日）を超えて古い … 「要確認」を出す。
3. 表示箇所 … サービス詳細のフッターと、一覧カード。一覧では「要確認のみ」で絞り込める。

**出力:** 各サービスに「要確認」バッジ（出す／出さない）。

**原則:** 文章生成（LLM）はしない。確認日としきい値の単純比較のみ。本ビューは**読み取り専用**。しきい値は `src/lib/freshness.ts` の `FRESHNESS_THRESHOLD_DAYS` で一元管理する。

---

## 共通の実装メモ

- いずれも `src/api/` が返す既存データから、表示層で組み立てる（新スキーマ不要）。
- 出典（どのフィールド／どの記事由来か）を必ず辿れるようにする＝信頼性の担保。
- 生成規則を変えたら本書を更新し、実装と一致させる。
