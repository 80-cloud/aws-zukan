# aws-zukan 評価ルーブリック（構成パターンの8軸判定基準）

**バージョン:** 0.1
**作成日:** 2026-06-26

構成パターンの評価（◎○△✕）を、人や日によってブレさせないための判定基準。AWS Well-Architected Framework の柱に対応づける。

---

## 記号の意味（共通）

- **◎** … その観点で明確に優れる／懸念がほぼない
- **○** … 標準的・許容範囲
- **△** … 注意が要る・弱点になりやすい
- **✕** … その要件には不適

> 軸ごとに「良い向き」が違う点に注意（例：運用負荷・コスト・ベンダー依存は**低いほど◎**）。下表の◎は常に「望ましい状態」を指す。

---

## 8軸の判定基準

| 軸 | 対応(Well-Architected) | ◎ | ○ | △ |
|---|---|---|---|---|
| **security** セキュリティ | セキュリティ | 公開範囲が最小・暗号化・最小権限・監査が既定で揃う | 標準的に守れる | 公開や権限が広くなりやすい・追加対策が要る |
| **availability** 可用性 | 信頼性 | 複数 AZ/リージョンで単一障害点がない | 単一 AZ だが復旧可 | 単一点があり停止しやすい |
| **opsLoad** 運用負荷 | 運用上の優秀性 | マネージドで手作業がほぼ不要（**負荷低**） | 一般的な運用で回る | パッチ・監視・手作業が多い（**負荷高**） |
| **cost** コスト | コスト最適化 | 従量・無料枠中心で**安い**／固定費小 | 標準的 | 常時課金・隠れコストが効きやすい（**高**） |
| **scalability** 拡張性 | パフォーマンス効率 | 自動スケールで増加に強い | 手動で拡張可 | スケールに作り直しが要る |
| **governanceFit** 統制適合 | （運用＋組織統制） | 承認・ログ・タグ・アカウント分離に素直に乗る | 工夫すれば適合 | 統制要件と相性が悪い |
| **migrationEase** 移行容易 | （持続可能性／可搬性） | 標準技術で他へ移しやすい | 一定の作業で移行可 | 強く結びつき移行が重い |
| **vendorLockin** ベンダー依存 | （可搬性） | AWS 固有依存が**低い**（移行容易と表裏） | 中程度 | 固有機能依存が**高い** |

---

## 採点の手順

1. 構成パターンの「標準推奨構成」を対象に採点する（不適合構成は `antiPatterns` 側で理由を書く）。
2. 各軸を上表に当てて ◎○△ を付ける。迷ったら**一段辛く**付け、`notes` に理由を書く。
3. `security` / `availability` が △ になる場合、`requiredGovernance` に対策を必ず1つ書く（弱点の放置を避ける）。
4. 判定根拠が公式（Well-Architected）にある場合は、その観点を `rationale` に一言残す。

---

## 一貫性チェック（自己点検）

- 同じサービス構成なのに別パターンで評価が食い違っていないか。
- ◎ が並びすぎていないか（「全部◎」は判定が甘いサイン）。
- 「良い向き」を取り違えていないか（opsLoad/cost/vendorLockin は低いほど◎）。
