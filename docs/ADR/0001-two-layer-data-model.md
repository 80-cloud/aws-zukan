# 0001. 2 層＋横断ルールのデータモデル

- ステータス: 採用

## 背景

AWS はサービスが多く、サービス単体の情報だけでは「どう組み合わせるか」「どんな構成が向く／向かないか」を引けない。

## 決定

データを 3 要素で持つ。

- サービス図鑑（部品表）: 各サービスの特徴・採用判断・運用情報。
- 構成パターン図鑑（設計判断集）: よくある構成と、標準推奨／不適合になりやすいポイント。
- 共通ルール: ネットワーク・IAM・暗号化・ログ等の横断ルールを正規化し、各サービスからは参照する（重複記載しない）。

## 結果

- 「設計判断」を引けるようになり、公式ドキュメントとの差別化になる。
- 横断ルールの重複が減り保守しやすい。
- 反面、データ間の参照整合を保つ仕組み（整合性チェックの CI）が必要になる。
