# aws-zukan

AWS のサービスを「部品表＋設計判断集」として引ける図鑑アプリ。
個々のサービスのスペックだけでなく、「どう組み合わせるか」「どんな構成が向く／向かない
か」までを、前提条件つきで引けることを目指す。

## データモデル

| 層 | 中身 |
|---|---|
| サービス図鑑 | 各 AWS サービスの部品としての特徴・採用判断・運用情報 |
| 構成パターン図鑑 | よくある構成と、標準推奨／不適合になりやすいポイント（設計判断集） |
| 共通ルール | ネットワーク・IAM・暗号化・ログ・タグ付け等、横断ルールの正規化 |

## 方針

- 断定しない：「正解／不正解」ではなく「標準推奨構成／不適合になりやすい構成」を前提条件つきで示す。
- 評価は 8 軸（Well-Architected 6 本柱＋独自 3 軸）を ◎○△ で表す。
- 記述は本文・公式を確認してから書き、出典を残す。未確認欄は空にする。

## ステータス

設計ドキュメント・評価ルーブリック・seed データ・テスト計画まで作成済み。
アプリ実装（フロントエンド）はこれから着手する段階。

- 設計: [docs/](docs/)
- データ: [data/](data/)（`services.json` / `patterns.json` / `common-rules.json`）

## 開発

- Phase 1（予定）: React + Vite + TypeScript + Tailwind、データは JSON seed をローカル読み込み。
- コミット前に用語・命名チェックが自動で走る。初回のみ `bash scripts/install-hooks.sh` を実行する。
