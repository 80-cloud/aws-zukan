# data/ — 図鑑の元データ（seed）

このフォルダは aws-zukan の中身（コンテンツ）を持つ。将来のフロントエンドは `src/api/` 経由でここを読む。

| ファイル | 内容 | スキーマ |
|---|---|---|
| `services.json` | サービス層（部品表） | docs/ER図.md の `Service` |
| `patterns.json` | 構成パターン層（設計判断集） | docs/ER図.md の `ConfigPattern` |
| `common-rules.json` | 共通ルール層（横断ルール） | docs/ER図.md の `CommonRule` |

## 出典の方針

各エントリの `realWorldNotes` と構成パターンの `antiPatterns[].source` は、**実際に踏んだ一次体験**へのリンクを持つ。推測で書かず、体験・検証済みの事実だけを「つまずき」として載せる（要件定義書の「決まった項目を埋める／自由作文しない」方針に沿う）。

現在の初版は、開発記録（https://qiita.com/80-cloud ）の AWS 系記事を変換したもの。サービス11件＋構成パターン5件に一次体験の注記つき。

サービスには **`adoption`（採用判断：廃止リスク/リージョン/クォータ/SLA/ロックイン/移行先）** と **`ops`（運用：IaC対応/バックアップ/変更影響/障害代替/データ越境）** のクラスタ、**`costGotcha`（隠れコスト）**、**`companions`（随伴サービス）** を持てる。構成パターンには `scenarioTags`（事例検索）・`stackRoles`（依存グラフ）を持てる。**これらの欄は捏造せず、確実に分かる事実のみ投入する（Tier 1 の高価値欄から段階的に）**。現状 adoption/ops は EC2/RDS/S3/ALB に投入済み、残りは順次。

## 追加の手順（要点）

1. `docs/ER図.md` の固定スキーマに沿って項目を埋める。
2. つまずき・注意は一次体験の出典つきで `realWorldNotes` に入れる（出典が無い一般知識は本文側に書き、`source` は省く）。
3. 公式リンクは各サービスの安定した代表ページを使う。
4. 追加後に JSON の妥当性と表記の一貫性を確認する。
